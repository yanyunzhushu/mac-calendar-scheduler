# 关键架构决策记录 (ADR)

## ADR-001: 使用 DateKey 字符串代替 Date 对象

**日期**: 2026年 早期

**决策**: 所有日期使用 `YYYY-MM-DD` 格式字符串（`DateKey` 类型），绝不使用 `Date` 对象。

**原因**:
- 避免时区问题（`Date` 对象在不同环境下可能表现不同）
- 字符串可直接作为对象键（`Record<DateKey, T>`）
- 字典序比较天然适用日期比较（`'2026-07-25' > '2026-07-24'`）
- 序列化/反序列化零损失

**代价**: 日期运算需通过 `date-utils.ts` 的工具函数（`addDays`、`diffDays` 等），不能直接使用 `Date` 方法。

## ADR-002: Static Export 代替 SSR

**日期**: 2026-06

**决策**: 使用 Next.js `output: 'export'` 静态导出，移除所有 API 路由。

**原因**:
- 应用为纯客户端，无服务端逻辑需求
- 简化部署（任何静态服务器即可）
- 为未来 Tauri 迁移做准备（Tauri 使用 WebView 加载静态文件）
- 避免维护 Node.js 服务端的开销

**代价**: 无法使用 Next.js 的 SSR/ISR/API Routes 功能。

---

## ADR-003: localStorage 全量持久化代替增量更新

**日期**: 2026年 早期

**决策**: 每次状态变化时将完整 `AppState` 整体序列化写入 localStorage（键名 `calendar-app-state`），而非增量更新。

**原因**:
- 实现简单，`useEffect` + `JSON.stringify` 即可
- 避免增量更新中的状态不一致
- 数据量小（个人日历应用，单用户），序列化开销可忽略
- 加载时只需一次 `JSON.parse`

**代价**: 大数据量下性能可能下降（当前场景不构成问题）。

## ADR-004: 移除 API 层，纯客户端运行

**日期**: 2026-06

**决策**: 删除 `app/api/` 目录，所有数据操作直接在浏览器中完成。

**原因**:
- 个人使用场景，无多用户同步需求
- 简化技术栈，降低维护成本
- 无网络依赖，离线可用
- 对隐私友好（数据不离开用户浏览器）

**代价**: 无法多设备同步，数据丢失风险由用户承担（可通过手动导出缓解）。

---

## ADR-005: 状态层纯函数与 React 分离

**日期**: 2026年 早期

**决策**: `lib/task-engine.ts`、`lib/date-utils.ts` 等核心逻辑保持纯函数，不依赖 React。

**原因**:
- 可独立测试和验证
- Tauri 迁移时无需修改这些文件
- 逻辑变更不影响 UI 层

**代价**: 状态管理需要额外的桥接层（`use-app-state.ts`）。

---

## ADR-006: 回收站保留到隔天 24 点

**日期**: 2026-07

**决策**: 删除任务后放入回收站，保留到次日 24 点（`expiresAt` = 删除日次日的 00:00:00 → 实际为当日+1 天的 24:00）。

**原因**:
- 给用户 1 天的反悔窗口
- 不会无限累积垃圾数据
- 分组任务支持级联恢复

---

## ADR-007: 进度任务跳过日（skipped）概念

**日期**: 2026-07

**决策**: 进度任务中，过去日期的实例如果进度条已覆盖但用户未操作 → `skipped`（已覆盖）；跳过区间内未覆盖 → `skipped`（未做）。今天始终为 `pending` 且可操作，与进度条覆盖状态无关。

**原因**:
- 进度条覆盖 ≠ 当天不可操作：提前量不应阻止当天完成
- 区分"已覆盖"和"未做"给用户清晰的进度感知
- 避免进度任务天天产生 missed 提醒（`countTodayMissed()` 明确排除进度任务）
